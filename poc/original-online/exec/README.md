# Isolated original executable replacement experiment

This profile prepares original `LoadExecPS2` syscall 6 for a browser process switch. It is separate from the default host and the local-Versus bridge. The original game and `NTGDVDJ.BIN` always use different WASM modules and documents; their overlapping EE addresses never share a dispatch registry. Research findings remain in [chapter 08](../../../docs/chapters/08-independent-clients.md#the-native-boundary-and-first-bounded-implementation).

The portable tests exercise request capture, native stack unwind, lifecycle failures, exact arguments, card ownership and actual browser document/storage adapters. Those browser tests use **synthetic documents**. A separate real game → utility → game cancel/return run passed on 2026-10-29, including both original syscalls, all three guest startup argument vectors, unchanged durable card bytes, and running/consuming audio. Full EE/IOP restart is an explicit experimental policy; it is not a claim of hardware `LoadExecPS2` equivalence. No configuration save, network connection or battle success is implied.

## Contract

1. Syscall 6 copies the live target, supplied count and every argument before changing any machine state. It records raw registers, syscall PC, thread and guest cycles. Only the exact genuine game/utility paths and opposite-image direction are accepted. Invalid pointers, non-ASCII bytes and payloads that SetupThread would truncate fail explicitly. Syscall 7 keeps its existing failure.
2. A typed C++ exception unwinds all guest-generated and nested-call frames to the outer `ps2::run()` host call. No old guest instruction resumes, no guest return value is fabricated, and no RAM/PC patch simulates success. Unknown targets also stop and report the actual error.
3. The storage profile supplies `extern "C" int ps2exec_checkpoint_card()`. The emulation thread invokes it after the unwind, with EE/IOP execution stopped. It must force all current card data to `/memcard/Mcd001.ps2`, check writes **and close**, and return zero only on success. A nonzero return is preserved. There is deliberately no default success stub. Upstream `flush_cards()` alone is insufficient: it delays 50 ticks, returns void and clears dirty before write success.
4. The main-thread callback exports the flushed MEMFS card. The parent commits it under a client-specific IndexedDB key, waits for transaction completion, and verifies SHA-256 through a new read transaction. A Web Lock covers the whole session, so a second tab cannot write that client's card. Child documents never mount IDBFS.
5. Only after durable readback does the parent terminate the old document's pthread workers, close its AudioContext, remove the iframe, and create the successor. Fresh WASM memory discards all EE/IOP/device/overlay/host state. The new document validates the actual preloaded ELF digest and imported card bytes before boot. Its startup receipt confirms the imported host arguments. A separate bounded, read-only first-SetupThread record captures the actual guest argc/argv after the original kernel copy; real proof requires that record too.

The original supplied argument vector is preserved without interpretation. The executable pathname is prepended once at boot. Game → utility supplies `[game_path, "1"]`, producing `[utility_path, game_path, "1"]`; the helper's normal return supplies `["1"]`, producing `[game_path, "1"]`. Nothing guesses the meaning of `1` or forces a menu state.

## Prepare and integrate

`build_profile.py` composes the native-storage owner's `prepare(tree)` with these overrides in a new copied runtime, compiles the changed sources, and links one executable. It does not edit either builder or the storage source. The game path retains the adaptive base and adds the original mode-7 observer; the utility path verifies original seed coverage and maps objects by full source path so the EE and IOP `kernel.cpp` cannot be confused.

```sh
python3 poc/original-online/exec/build_profile.py --image game \
  --base /private/game-build --sdk /private/emsdk --work .local/exec-game
python3 poc/original-online/exec/build_profile.py --image utility \
  --base /private/netutility-quiet --sdk /private/emsdk --work .local/exec-utility
```

The utility base must contain all recorded standalone source/object files, not only a browser package; `netutility-canonical2` is also supported. Its diagnostic object is rebuilt with the standalone utility's producer-quiet policy, so a full-trace baseline does not restore an earlier logging flood. Normal errors and bounded native exec/startup records remain visible. Every retained object and compiled input is fingerprinted; a failed command is preserved in `build-info.json`. Request the PC slot before running an actual build.

The retained PC game source/object bundle has no `web/build-info.json`. That one known archive pair is accepted only by its two exact historical SHA-256 values; the new manifest explicitly records absent web metadata and the archive-verification method. Unknown archive pairs without metadata are rejected. This does not manufacture an earlier build manifest or make the incremental link a fresh-source build.

Global helper qualification keeps this registry independent from the optional transport adapter's namespace. At fresh host initialization, this profile copies the retained module registry and replaces only the exact DNAS_NET descriptor after comparing every retained check word. All other images, including the browser image at the same address, remain registered. The ordinary dispatcher still requires the selected image's original code words; no address-only fallback is added. Native tests link the prepared dispatcher to fixture callbacks to verify correct selection, unchanged guest memory, preserved same-base sibling selection, and rejection after a single changed code word. They do not execute the original DNAS code or establish a real connection.

For diagnosis of original self-modifying code, export with `--guard-blocks`. This adds exact original-word checks at every generated label, including inline branch destinations, and bounded read-only records before and after translated direct transform calls. A changed block halts before its stale translation runs. Records retain original input registers, current registers, the affected bytes (at least 64 and at most 2048), and the preceding marker. Both allowlisted helpers normalize inverse starts to `a0 - (a1 XOR a2)` and capture the complete bounded range. Each helper has its own 64-call observation limit, and records identify the helper. This capture/stop profile does not execute transformed code. Native tests cover changed final bytes, inverse bounds and unchanged RAM.

`variant_prepare.py` adds an explicit experimental decoded-code layer to a guarded bundle. Supply the exact original artifact, a `block_codegen` executable, and `--variant HEX_BEGIN FIRST_CAPTURE SECOND_CAPTURE`; two independent fresh captures must agree on original arguments, preimage, output and marker. The compiler driver uses a retained compiler with its matching headers/objects. That retained compiler includes pre-existing fixes for external tail calls, absent fallthrough labels, initialized executable extents and MWo3 section discovery; it is not identical to pinned vendor source. Retain compiler source/object/binary hashes and those diffs. The driver preserves the analyzer/generator, rejects missing initial instructions and unguarded final delay slots, and records sparse analysis gaps when `--allow-sparse` is explicit. Skipped literal bytes remain in the complete range guard.

An optional reviewed `--candidate-catalog` with `--candidate-catalog-sha256` can pretranslate static candidates. These remain explicitly unverified until every actual range byte, including literals and excluded words, matches during original execution. No candidate bytes are copied into guest RAM. First selection records the actual words, marker and matched fingerprint once per range. The visible first-helper inventory contains 110 calls, 63 nonempty code ranges and one marker-only range; 18 even transforms have no visible inverse call. Explicit `--second-family-catalog` and `--second-family-catalog-sha256` options add the separately reviewed helper at `0x011E47C8`: 106 calls and 53 nonempty ranges, each with a visible inverse. The combined 117-range registry retains distinct original metadata and supports bounded first-match records above index 63. The profile never synthesizes an inverse or changes helper results.

Original range start/end seeds provide genuine continuation entries. The exporter separates protected bytes and markers from immutable module identity, guards every original/decoded label, and routes decoded entries and exits through the real dispatcher. Protected execution requires decoded bytes and the original self marker; encrypted or unknown execution, missing entries and re-encryption across a yield halt. Dispatch verifies the complete immutable code check set, while inline entries also check 32 immutable anchors and the complete current range. Original `FlushCache`/`iFlushCache` invalidate host selections while retaining their existing return behavior. Counter records expose the cost of full identity checks; this is an experimental host coherence policy, not a physical-cache equivalence claim. Native integration tests link the actual prepared dispatcher to fixtures, including altered literals/anchors, missing entries, inline dispatch, marker-only state, sibling images and re-encryption during a yield. Separate native tests execute the recompiler's first captured block to check its delay slot, exact instruction budget, forward overlap and preemption/resume.

Immutable identity uses the original MWo3 text section: offsets `0x40` through `0x40 + text_size`, excluding separately guarded protected ranges and markers. The exporter verifies the fixed address and exact header/text/data size sum. Writable data and BSS cannot identify an unchanged executable: original initialization legitimately changes those words. The manifest records section bounds and excluded check counts, and bounded rejection records retain the first mismatching code word or invalid marker. A separate read-only record identifies the first changed excluded data word against the former catalog, without using it for identity. A fresh original-mode7 run with this filter observed `0x012006F0` change from zero to one, then completed decode, execution and original inverse restoration of both initial ranges (`0x01181C84` and `0x01181D8C`). The next failure was the second helper setting its original marker at `0x011E5A50`, which the first-family profile still treated as immutable. That failure motivates the explicit second-family extension; it does not establish a service connection or battle. The combined profile subsequently matched 13 complete decoded ranges in a fresh run at `2026-10-29T05:09:04Z`, including six from the second helper. All 21 observed transform pairs matched original arguments and full bytes, including seven inverse restorations. It then stopped at the genuine original entry `0x011E87A8` with return address `0x011E8A7C`: module identity was valid, but its dispatch slot was absent. The 41-file private capture is `pc-capture-net-10/`; DHCP was observed, but no DNS/TCP service request, room entry or battle was established.

Decoded direct calls can expose original targets that static discovery of encrypted bytes never visited. `block_flow.hpp` adds a read-only audit to the compiler driver: it follows each decoded range from its entry, respects delay slots and trivial always/never branch facts, and records unresolved indirect calls. It does not change generated instructions. `entry_prepare.py` verifies the exact variant manifest, source words, original artifact, UnitInfo offsets and dispatch-table/case mapping before adding only missing original text seeds to a retained entries file. Internal C++ labels alone do not establish dispatch coverage. Targets in data, protected bytes or markers are rejected.

For an inventory, pass `--allow-missing-original-entries` to `variant_prepare.py`; such a bundle is analysis-only and the build profile rejects it. Run `entry_prepare.py --bundle ANALYSIS_BUNDLE --bundle-sha256 EXACT_SHA --artifact ORIGINAL_MWO --prior-entries RETAINED_ENTRIES --output NEW_SEED_DIRECTORY`, regenerate with the retained compiler's existing `--entries` option, export the guarded overlay, then prepare variants again without the exception. Final preparation requires all reachable original direct targets to have dispatch entries. Keep the other executable registries unchanged and independently inspect external-image targets.

The first audited closure retained 369 reachable external edges, rejected 16 skipped literal edges and added 34 original DNAS entries. All 23 separate-image targets already had retained main-executable dispatch slots; two indirect calls remain unresolved by this static audit. All 118 candidate translation sources were byte-identical before and after adding audit metadata. The retained compiler also discovered 88 additional labels while translating the new function extents; these are compiler artifacts, not additional justified seeds or observed paths. Every previous table entry and immutable check remains, while execution-PC guards reject nontext and 216 exact transform-table spans skipped by original unconditional branches. The spans exclude real delay slots and adjacent continuations; ordinary table reads and exact block-word guards remain intact. Tests include zero/self markers, non-marker table words, span boundaries, adjacent valid code and guards that legitimately include data words. This does not classify all other dead text literals. This is an experimental entry-discovery preparation, not a proven upstream compiler defect or a successful native connection; the regenerated profile still needs a fresh guest run.

## Combined native connection probe

`online-probe.cjs` is separate from the socket-blocking cancel probe. It accepts `PROBE_CLIENTS=1` or `2`, creating distinct browser contexts, card namespaces and executable documents, and reads private bridge configuration from `PROBE_NETWORK_CONFIG`. `private-config.cjs` accepts the network owner's gateway server JSON (`listen`, `token`, `endpoints`) or explicit client JSON (`gatewayURL`, `token`, `endpoints`); it projects the exact loopback route and rejects invalid configuration without echoing credentials. The probe permits only the private gateway's DNAS/lobby/battle/DNS WebSocket paths, scrubs the token from logs, records frame sizes/hashes without handshake headers, and keeps every browser muted with active audio.

For a targeted code-write investigation, `PROBE_WATCH=11e5a64,40` enables the original runtime's read-only write observer for that hexadecimal address and byte count before guest startup. The probe permits only an aligned RAM span of at most 256 bytes and records it in run provenance. This captures original store values and earlier values or bulk-copy words; it does not alter RAM or bypass code matching. Logs add overhead, so such a run is not a timing benchmark. Actual runtime-modified code still requires correct translation/invalidation or original execution support.

Use a fingerprinted card actually authored by the original utility. The probe follows the previously captured ordinary menu inputs only as far as the original settings menu, then waits for screenshot-led commands such as `{ "id": 1, "action": "press", "client": "A", "image": "game", "generation": 1, "state_word": 518, "code": "ArrowDown" }`. Send `{ "id": 2, "action": "finish" }` to retain a bounded capture and close the browser. A completed capture does not assert network or battle success; review the actual guest scenes and correlate both clients with backend evidence. A socket alone is insufficient.
